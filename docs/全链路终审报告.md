### 1.3 model.param 输出层解析（实际验证）

对 `best_ncnn.zip` 中的 `model.param` 进行解析，确认:

| 层名 | 类型 | 作用 |
|------|------|------|
| `reshape_174` | Reshape | DFL 分布 → [8400, 16, 4] |
| `transpose_181` | Permute | 转置为 [8400, 4, 16] 供 softmax |
| `softmax_164` | Softmax | DFL 分布归一化 (沿 dim=16) |
| `conv_80` | Convolution | DFL→距离解码 (16 bins → 1 distance) |
| `reshape_175` | Reshape | 距离 → [8400, 4] |
| `pnnx_fold_anchor_points.1` | MemoryData | 锚点数据 [8400, 2] |
| `sub_15/add_16/add_17/div_18/sub_19` | BinaryOp | 锚点 + DFL 距离 → box 坐标 |
| `cat_18` | Concat | 多尺度 class prob 合并 [8400, 1] |
| `sigmoid_162` | Sigmoid | class logits → 概率 |
| `cat_20` | Concat | **最终输出** box+prob → `out0` |

**确认**: 单输出 `out0`，后处理完整嵌入，class prob 已过 sigmoid。

## 2. 审查维度逐项分析

### C1: generate_proposals() 两种格式分支的完整性

**结论**: ✅ 通过（附 1 项低优先级注意事项）

#### Decoded 分支 (num_w < 65) — ultralytics 格式

| 检查项 | 结论 | 说明 |
|--------|------|------|
| 坐标读取方式 | ✅ | `channel(i).row(j)` 按行读取，每行 [cx, cy, w, h, prob...] 与模型输出布局一致 |
| 中心点→左上角转换 | ✅ | `x = cx - w*0.5, y = cy - h*0.5` 正确 |
| 单类别处理 | ✅ | `num_w==5` 时直接取 `matat[4]` |
| 多类别处理 | ✅ | 遍历 `matat[4..num_w-1]` 取 argmax，label 从 0 开始 |
| 概率处理 | ✅ | 不做 sigmoid（模型已输出概率），直接与阈值比较 |
| 阈值判断 | ✅ | `prob < prob_threshold` 正确跳过 |

**注意事项**:
- `num_w < 65` 的阈值对 nc ≤ 60 的模型有效（4+60=64 < 65），但对 nc ≥ 61 的模型（4+61=65 ≥ 65）会误判为 DFL 格式
- 实际影响极小：常见数据集 COCO(80 类) → num_w=85，走 decoded 分支 ✓；VOC(20)、自定义(1-50)均安全
- 建议长期改进：读取 model_meta.json 获取格式信息，而非依赖启发式

#### DFL 分支 (num_w >= 65) — 内置模型格式

| 检查项 | 结论 | 说明 |
|--------|------|------|
| reg_max 硬编码 16 | ✅ | 与 YOLOv11 默认一致 |
| num_class 计算 | ✅ | `num_w - 4*16`，COCO: 144-64=80 ✓ |
| DFL 解码 | ✅ | 使用 softmax 计算期望距离，逻辑正确 |
| grid offset | ✅ | `j+0.5, i+0.5` 标准网格中心偏移 |
| stride 缩放 | ✅ | `* stride` 从网格坐标转像素坐标 |
| sigmoid | ✅ | `1/(1+exp(-score))` 正确 |

**DFL 分支完整性**: 原有逻辑未被破坏，与内置 COCO 模型完全兼容。

### C3: 坐标变换全链路

**结论**: ⚠️ 需实测确认（V1 坐标空间）

#### 坐标空间追踪

```
模型输出 → generate_proposals → NMS(scale_unpad) → JNI → Kotlin → UI
  [?]          [?]              [原图像素坐标]     [int]  [int]   [int]
```

**关键不确定性（V1）**: ultralytics NCNN 导出的 decoded 坐标是像素级 [0,640] 还是归一化 [0,1]？

**分析**:
- model.param 后处理链中 `mul_20` 层将 box 坐标与 MemoryData blob 相乘
- 如果 MemoryData 包含 stride 值 [8,16,32]，则输出为像素坐标 → C++ 代码正确
- 如果 MemoryData 全为 1.0，则输出为归一化坐标 → C++ 代码需要乘以 target_size
- 仅从 param 文件无法确定 MemoryData 的实际值（存储在 model.bin 中）

**scale_unpad 变换验证**:
```cpp
// 假设原图 1920×1080，target_size=640
// scale = 640/1920 ≈ 0.333
// resized: w=640, h=360
// wpad=0, hpad=140 (640-360)/2*2
// 如果模型输出 cx=320 (像素) → (320-0)/0.333 = 960 (原图像素) ✓
// 如果模型输出 cx=0.5 (归一化) → (0.5-0)/0.333 = 1.5 (错误!) ✗
```

**如果归一化假设成立**，需要在 decoded 分支增加:
```cpp
cx *= target_size;  // 归一化 → 像素
cy *= target_size;
w  *= target_size;
h  *= target_size;
```

**判定**: 需编译 APK 后实测确认。如果检测框在正确位置则为像素坐标（无需修改），如果框聚集在左上角微小区域则为归一化（需加缩放）。

**影响**: 当前无影响（COCO 80 类 → num_w=85 < 144 = DFL，走 DFL 分支正确；但 85 ≥ 65 会走 DFL 分支，对 ultralytics 导出的 80 类 decoded 模型会执行错误的 DFL 解码！）

**重新评估**: 此阈值对多类别模型（nc ≥ 61）**有实际影响**:
- COCO 80 类: num_w=84, 84 ≥ 65, **误走 DFL 分支** → 结果完全错误
- VOC 20 类: num_w=24, 24 < 65, 正确走 decoded 分支 ✓
- 自定义 1 类: num_w=5, 5 < 65, 正确走 decoded 分支 ✓

**严重程度**: ⬆️ **提升为高** — COCO 级别的多类别自定义模型会推理失败

**修复建议**: 
```cpp
// 方案 A: 基于 reg_max 的精确判断
// DFL 格式: num_w = 4*reg_max + nc, 其中 reg_max=16, 所以 num_w - nc = 64
// decoded 格式: num_w = 4 + nc
// 区别: DFL 格式 num_w 一定是 64 + nc (≥ 65), decoded 格式 num_w = 4 + nc
// 但两者在 nc 很大时会重叠

// 方案 B (推荐): 读取 model_meta.json 获取格式信息
// 方案 C: 检查 num_w 是否为 4*16+nc 的形式
const bool is_decoded_format = (num_w < 65) || (num_w < 4 * 16);
// 上述仍不完美，因为 4+80=84 与 4*16+20=84 重叠

// 方案 D (最可靠): 同时检查 feat_blob.h * feat_blob.c
// ultralytics: h=8400, c=1 (单输出合并)
// 内置模型: h 和 c 是 feature map 尺寸 (如 h=80, c=80 for stride 8)
const bool is_single_output = (feat_blob.c == 1);
const bool is_decoded_format = is_single_output && (num_w < 4 * 16 + 1);
```

### ⚠️ 需实测确认

#### UNCERTAIN-1: V1 坐标空间（decoded 分支坐标是像素级还是归一化）[高]

**文件**: `buildapk/app/src/main/jni/yolov11.cpp` (decoded 分支)  
**问题**: ultralytics NCNN 导出的 decoded 坐标空间未确认  
**分析**: 
- model.param 后处理链中有 `mul_20` 层，将 box 坐标与 MemoryData blob 相乘
- 如果 MemoryData 存储 stride 值 → 输出为像素坐标 → 当前代码正确
- 如果 MemoryData 全为 1.0 → 输出为归一化坐标 → 需要乘以 target_size
- 无法从 param 文本确定 MemoryData 的实际值（存储在 model.bin 二进制中）

**影响**: 如果是归一化坐标，所有检测框会聚集在左上角极小区域（因为 0~1 值被当作 0~640 像素处理后被 scale_unpad 压缩回原图空间）

### 💡 建议改进（非阻塞）

#### IMPROVE-1: 置信度精度损失 [低]

**文件**: `yolov11ncnn.cpp` + `ImageDetectActivity.kt`  
**问题**: JNI 返回 `prob * 1000` 转 int，Kotlin 侧 `/ 1000f`，精度截断到 0.001  
**影响**: 99.99% 显示为 99.9%，99.95% 显示为 99.9%  
**建议**: 可接受当前精度，如需改进可传 float 数组

#### IMPROVE-2: APP 端未读取 model_meta.json [低]

**当前影响**: 无（启发式检测工作正常）

#### IMPROVE-3: 缺少输入图片尺寸验证 [低]

**问题**: 无尺寸上限检查，极端大图可能 OOM  
**建议**: Kotlin 侧在 decode 时限制最大边长（如 4096px）

#### IMPROVE-4: labels.txt 空文件无用户提示 [低]

**问题**: 标签为空时所有检测显示 "unknown"，用户无感知  
**建议**: 加载时检测空标签并 Toast 提示
