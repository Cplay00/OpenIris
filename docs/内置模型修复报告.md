# 内置 YOLOv11n 模型推理异常修复报告

## 问题描述

用户报告：自训练模型（ultralytics 导出）可正常识别，但内置 YOLOv11n 模型出现：
1. 识别标签不准
2. 置信度极高异常值（450%）

## 根因分析

### 1. 内置模型输出维度推断

通过分析 `model.param` 文件的最后几层操作，追踪维度变化：

```
Convolution  conv_80         1 1 289 290  0=64 ...    # DFL 分支: c=64, h=S, w=S
Permute      permute_176     1 1 290 291  0=3         # Permute 0=3: w=64, h=S, c=S
Convolution  convsigmoid_2   1 1 288 292  0=80 9=4    # 分类分支: c=80, h=S, w=S
Permute      permute_175     1 1 292 293  0=3         # Permute 0=3: w=80, h=S, c=S
Concat       cat_17          2 1 291 293 out2  0=2    # Concat axis=2(w): w=144, h=S, c=S
```

**ncnn Permute `0=3` (CWH) 语义**（源码确认）：
```cpp
// top_blob.create(channels, w, h, ...) → new_w = old_c, new_h = old_w, new_c = old_h
top_blob.create(channels, w, h, elemsize, opt.blob_allocator);
```

**ncnn Concat `0=2` 对 3D Mat 的轴映射**：
```
axis 0 = c (channels)
axis 1 = h (height)
axis 2 = w (width)  ← 本模型使用此轴
```

Permute 0=3 将 DFL(64) 和 class(80) 通道都放到 w 维度，然后 Concat 沿 w 拼接。

**最终输出维度**：

| stride | 空间 S | w (特征) | h (空间) | c (空间) |
|--------|--------|----------|----------|----------|
| 8      | 80     | 144      | 80       | 80       |
| 16     | 40     | 144      | 40       | 40       |
| 32     | 20     | 144      | 20       | 20       |

### 2. Bug 根因

原格式检测代码（第 73 行）：
```cpp
const bool is_decoded_format = !(num_c > 1 && num_c >= 4 * 16 && num_w > 1 && num_h > 1);
```

此检查仅验证 `num_c >= 64`，但经过 Permute 后特征维度从 c 转移到了 w：
- c = S（空间维度 20/40/80），**不是**特征维度
- w = 144（特征维度），**包含** DFL + 分类数据

**各 stride 的检测结果**：

| stride | num_c | num_w | num_h | c >= 64? | 实际格式 | 检测结果 | 正确？ |
|--------|-------|-------|-------|----------|----------|----------|--------|
| 32     | 20    | 144   | 20    | ❌ (20<64) | DFL    | decoded  | ❌ BUG |
| 16     | 40    | 144   | 40    | ❌ (40<64) | DFL    | decoded  | ❌ BUG |
| 8      | 80    | 144   | 80    | ✅ (80≥64) | DFL    | DFL      | ✅     |

stride 32 和 16 错误地走 decoded 分支，导致：
- **标签错误**：DFL 回归值（位置 0-63）被当作分类分数读取
- **450% 置信度**：DFL 回归原始值可以是 4.5 这样的大数，直接作为 `obj.prob` 使用

decoded 分支的错误数据访问（stride 32 为例）：
```
ptr[0..3]   → DFL 回归特征被当作 x1,y1,x2,y2 坐标 → 边界框完全错误
ptr[4..63]  → DFL 回归特征被当作分类分数 → 找到的最大"分数"是 DFL 原始值（可能 >> 1.0）
ptr[64..143]→ 真正的分类分数（sigmoid 激活，0~1）被忽略
obj.prob = max_prob（无 sigmoid 保护）→ 450% 置信度
```

## 修复方案

### 修改内容

**文件**：`buildapk/app/src/main/jni/yolov11.cpp`（第 73→76 行）

```cpp
// 修复前：
const bool is_decoded_format = !(num_c > 1 && num_c >= 4 * 16 && num_w > 1 && num_h > 1);

// 修复后：
// 内置模型经过 Permute 0=3 + Concat axis=w 后,特征沿 w 维度(144),空间沿 c 和 h 维度
// 因此需要同时检查 c 和 w 是否包含 DFL 特征维度(>= 64)
const bool is_decoded_format = !(num_c > 1 && num_w > 1 && num_h > 1 && (num_c >= 4 * 16 || num_w >= 4 * 16));
```

### 修复逻辑

新增 `|| num_w >= 4 * 16` 条件，同时检查 c 和 w 两个维度是否包含 DFL 特征（≥64）。

这样无论特征沿 c（标准布局）还是沿 w（Permute 后的内置模型布局），都能正确检测 DFL 格式。

### 为什么 DFL 分支代码无需修改

内置模型的 DFL 分支处理已经正确：
```cpp
// 数据访问：channel(i).row(j) 恰好指向空间位置 (i,j) 的 144 个特征
const float* matat = feat_blob.channel(i).row(j);

// DFL 沿 w 维度的前 64 个值：matat[0..63]
float x0 = j + 0.5f - softmax(matat, dst, 16);      // DFL_left
float y0 = i + 0.5f - softmax(matat + 16, dst, 16);  // DFL_top
float x1 = j + 0.5f + softmax(matat + 2*16, dst, 16);// DFL_right
float y1 = i + 0.5f + softmax(matat + 3*16, dst, 16);// DFL_bottom

// 分类分数在 w 维度的后 80 个值：matat[64..143]
float score = matat[4 * reg_max + c];  // c = 0..79

// sigmoid 激活保护
obj.prob = 1.0f / (1.0f + exp(-class_score));  // 输出 ∈ (0, 1)
```

## 影响范围

- **修改文件**：仅 `yolov11.cpp` 的 `generate_proposals()` 函数
- **修改行数**：1 行代码 + 2 行注释
- **不修改**：`runInference()` 函数
- **风险**：极低。仅扩展格式检测条件，不影响已有的 decoded 和 DFL 处理逻辑

## 关键结论

内置模型的 Permute 0=3 操作将特征维度从 c 转移到了 w 维度。原代码仅检查 `num_c >= 64` 来判断 DFL 格式，遗漏了特征在 w 维度的情况。修复后同时检查 c 和 w，确保两种布局都能正确识别。
