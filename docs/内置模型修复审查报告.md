## 1. 修复概述

### 1.1 修改内容

**修复前**:
```cpp
const bool is_decoded_format = !(num_c > 1 && num_c >= 4 * 16 && num_w > 1 && num_h > 1);
```

**修复后**:
```cpp
const bool is_decoded_format = !(num_c > 1 && num_w > 1 && num_h > 1 && (num_c >= 4 * 16 || num_w >= 4 * 16));
```

### 1.2 根因分析

内置 YOLOv11n 模型使用 Permute 0=3 (CWH) + Concat 0=2，将特征维度从 c 转移到了 w：

| stride | w (特征) | h (空间) | c (空间) |
|--------|----------|----------|----------|
| 32     | 144      | 20       | 20       |
| 16     | 144      | 40       | 40       |
| 8      | 144      | 80       | 80       |

修复前的逻辑只检查 `c >= 64`，导致 stride 32 和 stride 16 的内置模型被错误识别为 decoded 格式。

## 3. DFL 分支兼容性分析

### 3.1 DFL 分支代码未被修改

经检查，修复仅修改了 `is_decoded_format` 的判断逻辑，DFL 分支的处理代码保持不变。

### 3.2 DFL 分支数据访问方式

DFL 分支代码（简化版）:
```cpp
const int reg_max = 16;
float dst[16];
const int num_class = num_w - 4 * reg_max;  // 144 - 64 = 80

for (int i = 0; i < num_c; i++)      // grid_y (空间高度): 0..19
{
    for (int j = 0; j < num_h; j++)  // grid_x (空间宽度): 0..19
    {
        const float* matat = feat_blob.channel(i).row(j);
        // matat 指向 [144] 个浮点数
        // matat[0..15]: DFL_left
        // matat[16..31]: DFL_top
        // matat[32..47]: DFL_right
        // matat[48..63]: DFL_bottom
        // matat[64..143]: class_logits (80类)
    }
}
```

### 3.3 数据布局验证

对于内置模型 [c=20, h=20, w=144]：

| 维度 | 值 | 含义 |
|------|-----|------|
| c | 20 | grid_y (垂直位置) |
| h | 20 | grid_x (水平位置) |
| w | 144 | 特征维度 (DFL_left(16) + DFL_top(16) + DFL_right(16) + DFL_bottom(16) + class_logits(80)) |

**DFL 数据布局**: [DFL_left(16), DFL_top(16), DFL_right(16), DFL_bottom(16), class_logits(nc)]

**坐标计算**:
```cpp
float x0 = j + 0.5f - softmax(matat, dst, 16);        // j 是 grid_x
float y0 = i + 0.5f - softmax(matat + 16, dst, 16);   // i 是 grid_y
float x1 = j + 0.5f + softmax(matat + 2 * 16, dst, 16);
float y1 = i + 0.5f + softmax(matat + 3 * 16, dst, 16);

x0 *= stride;
y0 *= stride;
x1 *= stride;
y1 *= stride;
```

**结论**: DFL 分支能正确处理 [c=20, h=20, w=144] 布局 ✅
