## 1. 修复概述

### 1.1 Euler 修复（格式检测条件优化）

**修复前**（Russell 版本）:
```cpp
const bool is_decoded_format = !(num_c > 1 && num_w >= 4 * 16);
```

**修复后**（Euler 版本）:
```cpp
const bool is_decoded_format = !(num_c > 1 && num_c >= 4 * 16 && num_w > 1 && num_h > 1);
```

**改进点**:
- 条件从 `num_w >= 64` 改为 `num_c >= 64`（更准确地反映 DFL 格式的通道特征）
- 增加 `num_w > 1` 和 `num_h > 1` 空间维度检查，避免误判边界情况

### 1.2 Russell 修复（2D blob 处理）

新增 `num_c == 1` 分支，处理 ultralytics 导出的 2D blob 格式 `[c=1, h=values, w=anchors]`:
```cpp
if (num_c == 1) {
    // 2D blob: [c=1, h=values, w=anchors]
    values_in_w = false;
    num_anchors = num_w;
    num_values = num_h;
}
```

## 3. 边界条件检查

### 3.1 边界情况分析

#### Case A: `num_c == 1, num_h == 1, num_w == 8400`
```
is_decoded_format = !(num_c > 1 && ...) = !(FALSE && ...) = TRUE → Decoded

进入 num_c == 1 分支:
├─ num_anchors = 8400
├─ num_values = 1
├─ 检查: num_values < 5 → TRUE → 触发错误日志并 return
```
**结果**: ⚠️ 正确拒绝无效形状（无误检测风险），但会静默跳过

#### Case B: `num_c == 1, num_h == 5, num_w == 1`
```
is_decoded_format = !(num_c > 1 && ...) = !(FALSE && ...) = TRUE → Decoded

进入 num_c == 1 分支:
├─ num_anchors = 1
├─ num_values = 5
├─ 检查通过 (5 >= 5, 1 > 0)
├─ 循环: for (i = 0; i < 1; i++) → 只处理 1 个 anchor
└─ 读取数据: feat_blob.channel(0).row(0..4)[0]
```
**结果**: ✅ 正确处理单锚点情况

#### Case C: `num_c == 144, num_h == 1, num_w == 1`
```
is_decoded_format = !(num_c > 1 && num_c >= 64 && num_w > 1 && num_h > 1)
                 = !(TRUE && TRUE && FALSE && TRUE)
                 = TRUE → **Decoded**（本应是 DFL）

问题: DFL 数据被当作 Decoded 处理
├─ num_c > 1 分支: num_anchors = 144, num_values = 1
├─ 检查: num_values < 5 → TRUE → 触发错误日志并 return
```
**结果**: 🐛 **BUG** - 错误分类导致无法检测目标

### 3.2 Euler 条件弱点分析

当前 Euler 条件:
```cpp
const bool is_decoded_format = !(num_c > 1 && num_c >= 4 * 16 && num_w > 1 && num_h > 1);
```

**弱点**: 当 `num_h == 1` 或 `num_w == 1` 时，条件为 FALSE，导致 `is_decoded_format = TRUE`，将 DFL 格式误判为 Decoded。

**受影响场景**:
| 场景 | 维度 | 正确格式 | 实际判断 | 影响 |
|------|------|----------|----------|------|
| 极端 stride | `[c=144, h=1, w=X]` | DFL | Decoded | 无法检测 |
| 极端 stride | `[c=144, h=X, w=1]` | DFL | Decoded | 无法检测 |
| 边界情况 | `[c=144, h=1, w=1]` | DFL | Decoded | 无法检测 |

**发生概率**: 低（仅在极端空间维度时出现）

## 4. DFL 分支兼容性

### 4.1 DFL 分支代码审查

```cpp
// Raw DFL format: [DFL_left(16), DFL_top(16), DFL_right(16), DFL_bottom(16), class_logits(nc)]
const int reg_max = 16;
float dst[16];
const int num_class = num_w - 4 * reg_max;  // num_w - 64

for (int i = 0; i < num_c; i++)       // 空间维度 1 (grid_y 或 grid_x)
{
    for (int j = 0; j < num_h; j++)   // 空间维度 2
    {
        const float* matat = feat_blob.channel(i).row(j);

        // 类别得分计算
        int class_index = 0;
        float class_score = -FLT_MAX;
        for (int c = 0; c < num_class; c++)
        {
            float score = matat[4 * reg_max + c];
            if (score > class_score) {
                class_index = c;
                class_score = score;
            }
        }

        if (class_score >= prob_threshold)
        {
            // DFL 距离解码
            float x0 = j + 0.5f - softmax(matat, dst, 16);
            float y0 = i + 0.5f - softmax(matat + 16, dst, 16);
            float x1 = j + 0.5f + softmax(matat + 2 * 16, dst, 16);
            float y1 = i + 0.5f + softmax(matat + 3 * 16, dst, 16);

            x0 *= stride;
            y0 *= stride;
            x1 *= stride;
            y1 *= stride;

            Object obj;
            obj.rect.x = x0;
            obj.rect.y = y0;
            obj.rect.width = x1 - x0;
            obj.rect.height = y1 - y0;
            obj.label = class_index;
            obj.prob = 1.0f / (1.0f + exp(-class_score));  // sigmoid
            objects.push_back(obj);
        }
    }
}
```

### 5.2 发现的问题

#### 🐛 Bug #1: 边界空间维度误判

**严重性**: 中等

**问题**: 当 `num_h == 1` 或 `num_w == 1` 时，Euler 条件无法正确识别 DFL 格式。

**影响**: 极端 stride 的模型输出无法被正确解析。

**复现条件**:
- 输入维度: `[c=144, h=1, w=80]` 或 `[c=144, h=80, w=1]`

**触发场景**: stride 640 或更高（640/640 = 1）

**建议修复**:
```cpp
const bool is_decoded_format = !(num_c > 1 && num_c >= 4 * 16 && (num_w > 1 || num_h > 1));
```
或更严格的：
```cpp
const bool is_decoded_format = (num_c == 1) || (num_c < 4 * 16);
```

#### ⚠️ 注意 #2: reg_max 硬编码

**严重性**: 低

**问题**: `reg_max = 16` 硬编码，仅适用于 YOLOv8/v11 默认配置。

**影响**: 如果用户使用自定义 reg_max 的模型，会导致解析错误。

**建议**: 从模型参数或 blob 尺寸动态推断 reg_max。
