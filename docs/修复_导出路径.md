# 修复报告：导出路径无效（P0）

**日期**: 2026-06-17  
**问题类型**: P0 - 功能完全不可用  
**影响范围**: PyInstaller 打包的 EXE 模式下，导出功能完全失效

---

## 问题描述

当 `IS_PACKAGED=True` 时（即 PyInstaller 打包的 EXE 模式），`_export_model()` 方法中的逻辑在 `find_python()` 返回 `None` 时仅输出一行提示信息，完全不执行导出操作：

```
Export requires Python environment. Use command line.
```

用户手动选择的模型路径和输出目录全部被忽略，导出流程中断。

## 根因分析

```python
# 原代码（main_window.py 第 738-741 行）
python_exe = find_python()
if python_exe is None:
    self._log(f"{t('export')}... (direct mode)")
    self._log("Export requires Python environment. Use command line.")
    # ← 无后续操作，直接返回
```

`find_python()` 在打包模式下的查找路径为：
1. `exe_dir/_internal/python.exe`
2. `exe_dir/_internal/python3.exe`
3. `exe_dir/python.exe`
4. 系统 `python`（通过 `shutil.which`）

若以上均不存在，返回 `None`。此时导出功能直接跳过。

## 修复方案

参照 `_validate_direct()` 的模式（第 703-715 行），在打包模式下直接调用 `export_pipeline.main()`：

`training/gui/main_window.py` — `_export_model()` 方法

### 修复逻辑说明

| 条件 | 行为 |
|------|------|
| `IS_PACKAGED=True` 且 `python_exe=None` | **新增**：直接调用 `export_pipeline.main()`（与 `_validate_direct` 同模式） |
| `python_exe` 有值（非打包模式或打包模式下找到 Python） | 原有逻辑不变，通过子进程调用 |
| `IS_PACKAGED=False` 且 `python_exe=None` | 原有逻辑不变，输出错误提示 |

## 验证

- 修改后，打包模式下 `find_python()` 返回 `None` 时，仍会正常执行导出
- `sys.argv` 设置与子进程命令行参数一致（`--weights`, `--output`, `--format`）
- `try/finally` 保证 `sys.argv` 在异常后恢复
- `except Exception` 捕获导出过程中的错误并输出到日志面板
