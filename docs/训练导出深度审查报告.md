## 1. 问题概述与根因确认

### 1.1 三重异常现象

| 异常 | 表现 | 原因 |
|------|------|------|
| 标签全 unknown | 所有检测框显示 "unknown" | C++ `getClassName()` 查找 `class_names[label]`，label 值溢出导致 fallback |
| 框图在左上角 | 所有检测框聚集在图像左上角 | C++ DFL 解码时读取了已解码坐标再次解码，产生垃圾坐标 |
| 置信度 100% | 所有框的置信度显示为 100% | C++ 对已经过 sigmoid 的概率值再次执行 sigmoid |

### 1.2 根本原因（已确认）

**ultralytics 的 NCNN 导出会自动在模型图内嵌入完整的后处理流程**（DFL 解码 + 锚点计算 + sigmoid），导出的模型只有 **单个输出 `out0`**，格式为 `[5, 8400]`（4 个已解码坐标 + 1 个 sigmoid 概率 × 8400 个 anchor）。

但 C++ 推理代码 `yolov11.cpp` 期望的是 **原始 YOLO 输出格式**：
- 3 个输出 `out0`, `out1`, `out2`（对应 stride 8/16/32）
- 每个输出 shape 为 `[64+nc, H, W]`（64 = reg_max×4 = 16×4，nc = 类别数）
- 需要自行执行 DFL softmax + grid 解码 + sigmoid

**结论**：模型输出端已完成全部后处理，C++ 又对其执行了一遍相同的后处理，导致结果全错。

### 1.3 社区验证

此问题在社区中已有大量报告：
- CSDN 文章确认："score 不需要 sigmoid，矩形框坐标和尺寸不需要 softmax 转换，ultralytics 的转换工具已经帮你做好了"
- GitHub Tencent/ncnn#5795 确认："使用官方工具导出的只有 out0，而官方 yolo11.cpp 都是 out0,out1,out2"
- GitHub taiji1985/yolo11-ncnn 项目专门为此问题编写了适配代码

## 3. export_pipeline.py 详细分析

### 3.1 文件概述

- **路径**: `training/tools/export_pipeline.py`
- **行数**: 374 行
- **功能**: 封装 ultralytics YOLO.export()，提供 .pt → NCNN 的一键导出

### 3.2 核心导出流程（6 步）

```python
# Step 1: 加载模型
model = YOLO(weights_path)

# Step 2: 导出 NCNN（关键调用）
model.export(format='ncnn', imgsz=imgsz)  # ← 后处理自动嵌入发生在此处

# Step 3: 生成 labels.txt（从 .pt 模型提取类名）
# Step 4: 复制到输出目录
# Step 5: 打包 zip
# Step 6: 复制到 Android assets
```

### 3.3 关键问题

#### 🔴 E1: 文档注释与实际导出格式严重不一致

```python
# 第 20-21 行文档声称：
# 4. 输入图像预处理: resize 到 640x640, BGR->RGB, /255.0
# 5. 输出: [class_id, confidence, x, y, w, h] (归一化坐标)

# 实际 ultralytics NCNN 导出的输出格式：
# out0: [5, 8400] = [4个已解码坐标 + 1个sigmoid概率, 8400个anchor]
# 坐标为像素值(cx, cy, w, h)，概率已经过sigmoid
```

**影响**: 误导后续 C++ 开发者按照错误格式编写后处理代码。

#### 🔴 E2: 无法控制 ultralytics NCNN 导出的后处理行为

```python
def export_ncnn(weights_path, imgsz=640, half=False):
    model = YOLO(weights_path)
    # 直接调用 export，无任何后处理控制参数
    model.export(format='ncnn', imgsz=imgsz, half=half)
```

**分析**: ultralytics 的 `YOLO.export(format='ncnn')` 会：
1. 将 PyTorch 模型导出为 ONNX
2. 通过 PNNX 将 ONNX 转换为 NCNN
3. **在 PNNX 转换过程中，自动将 Detect head 的后处理（DFL 解码、锚点计算、sigmoid）折叠进模型图**

这个过程是 ultralytics 内部自动完成的，export_pipeline.py 没有任何参数可以控制或禁用此行为。

#### 🟡 E3: 颜色空间文档误导

文档声称 "BGR→RGB"，但：
- ultralytics 训练时使用 RGB 输入
- C++ NCNN 推理代码保持 BGR 输入
- 模型期望 RGB，实际收到 BGR → 红蓝通道互换

#### 🟡 E4: 未记录 reg_max 参数

```python
# export_ncnn 函数中完全没有记录 reg_max
# reg_max 默认值为 16（ultralytics 内部），但从未写入任何元数据
# 如果训练时修改了 reg_max，C++ 端无法得知
```

#### 🟢 E5: labels.txt 生成的编码问题

```python
# generate_labels() 从 .pt 模型提取类名
# labels.txt 内容为 "pig\r\n"（Windows 换行符）
# C++ 代码有 strip 处理，实际影响不大
```

#### 🟢 E6: 缺少导出元数据记录

```python
# 导出完成后未记录：
# - 输入尺寸 (imgsz)
# - 颜色空间 (RGB/BGR)
# - 归一化方式 (/255.0)
# - reg_max 值
# - nc（类别数）
# - 输出格式说明
# 这些信息对于 C++ 端正确实现后处理至关重要
```

### 3.4 ONNX 专用导出函数

```python
def export_onnx_only(weights_path, imgsz=640, simplify=True, opset=12):
    model = YOLO(weights_path)
```

- 导出后 C++ 端无法正确解析输出

## 5. ultralytics NCNN 导出后处理嵌入机制详解

### 5.1 导出流程概览

```
PyTorch 模型 (.pt)
    │
    ├─ 1. 加载模型 + 权重
    │
    ├─ 2. 导出 ONNX
    │     └─ model.export(format='onnx')
    │        - 包含完整的前向传播
    │        - Detect head 的输出为原始格式
    │
    ├─ 3. PNNX 转换 (ONNX → NCNN)
    │     └─ ultralytics 内部的 PNNX 处理
    │        - 自动折叠 Detect head 的后处理
    │        - 将 DFL softmax + Conv1x1 + anchor 解码 内联到图中
    │        - 将 sigmoid 内联到分类分支
    │        - 生成单个输出 out0
    │
    └─ 4. 输出 NCNN 模型
          ├─ model.param (结构定义)
          ├─ model.bin   (权重数据)
          └─ 自动生成的后处理层
```

### 5.2 后处理嵌入的具体过程

ultralytics 在 PNNX 转换阶段会执行以下操作：

#### 5.2.1 DFL 解码折叠

```python
# 原始 YOLO 输出（每个 anchor）
# bbox_pred: [64, H, W] = [reg_max*4, H, W]  # 16×4=64 个 DFL 值
# cls_pred: [nc, H, W]                        # nc 个分类 logits

# PNNX 折叠后的操作：
# 1. Reshape: [64, 8400] → [4, 16, 8400]
# 2. Softmax: 对每个 16 元素做 softmax → [4, 16, 8400]
# 3. Conv1x1 (0,1,2,...,15): 16元素加权求和 → [4, 8400]  # DFL→距离值
# 4. MemoryData anchor_points: 预计算的 anchor 中心坐标 [8400, 2]
# 5. BinaryOp: 距离值→坐标转换 (xywh 格式)
# 6. Reshape: 最终坐标 [4, 8400]
```

#### 5.2.2 分类 sigmoid 折叠

```python
# 原始: cls_pred [nc, 8400] (logits)
# 折叠后: Sigmoid(cls_pred) → [nc, 8400] (概率)
```

#### 5.2.3 最终输出拼接

```python
# Concat([decoded_bbox, sigmoid_scores]) → [4+nc, 8400]
# 对于单类别(pig): [5, 8400]
# 对于 COCO 80 类: [84, 8400]
```

### 5.3 model.param 中的后处理层序列

```
# === DFL 解码部分 ===
Reshape     reshape_175    # [64, 8400] → [4, 16, 8400]
Softmax     softmax_0      # 对每组 16 元素做 softmax
Convolution conv_??        # 1×1 卷积，权重 [0,1,2,...,15]，实现加权求和
Reshape     reshape_??     # → [4, 8400] (距离值)

# === 锚点计算部分 ===
MemoryData  pnnx_fold_anchor_points.1  # 预计算的 anchor 中心 [8400, 2]
Slice       chunk_0        # 将距离值拆分为 left/top/right/bottom
BinaryOp    sub_15         # cx = anchor_x - left
BinaryOp    add_16         # cy = anchor_y + top  (实际是 + 后再调整)
BinaryOp    add_17         # 中间计算
BinaryOp    div_18         # 除以 2.0
BinaryOp    sub_19         # 中间计算
Concat      cat_19         # 拼接为 [4, 8400] (cx, cy, w, h)

# === 宽高缩放 ===
Reshape     reshape_176    # [1, 8400] → [8400, 1]
BinaryOp    mul_20         # 坐标 × stride 缩放

# === 分类 sigmoid ===
Sigmoid     sigmoid_162    # 对分类 logits 做 sigmoid

# === 最终输出 ===
Concat      cat_20         # [decoded_bbox, sigmoid_scores] → [5, 8400]
                            # 输出为 out0
```

### 5.4 关键证据

#### 证据 1: 单输出
```
# model.param 第 2 行
274 326
# 274 = blob 数量, 326 = 层数量
# 最后一层: Concat cat_20 → out0 (只有 1 个输出)
```

#### 证据 2: MemoryData 锚点预计算
```
MemoryData  pnnx_fold_anchor_points.1  0 1 307  0=8400 1=2
# 0 1 = 无输入，1 个输出
# 0=8400 1=2 = 形状 [8400, 2] = 8400 个 anchor 的 (cx, cy) 坐标
```

#### 证据 3: Sigmoid 内联
```
Sigmoid     sigmoid_162    1 1 301 324
# 对 blob 301 (分类 logits) 做 sigmoid → blob 324
```

#### 证据 4: DFL Conv1x1 权重
```
# 1×1 卷积权重为 [0, 1, 2, ..., 15]
# 这是 DFL 的核心：softmax 后与 [0..15] 加权求和
# 实现了 ∑(i * softmax_i) = 期望值
```

## 6. model.param 结构分析

### 6.1 基本信息

```
magic_number: 7767517
layer_count: 326
blob_count: 274
input: in0 (1, 3, 640, 640) = 3通道 640×640
output: out0 (5, 8400) = 5个值 × 8400个anchor
```

### 6.2 输出格式详解

```
out0 的 5 个值（对于 1 类 pig）:
  [0]: cx - 检测框中心 x 坐标（像素值，已乘 stride）
  [1]: cy - 检测框中心 y 坐标（像素值，已乘 stride）
  [2]: w  - 检测框宽度（像素值，已乘 stride）
  [3]: h  - 检测框高度（像素值，已乘 stride）
  [4]: sigmoid(pig) - pig 类的 sigmoid 概率

# 注意：坐标是像素值（0~640），不是归一化值（0~1）
# 需要除以 640 才能得到归一化坐标
```

### 6.3 与标准 YOLO 输出格式的对比

| 项目 | ultralytics NCNN 导出 | 标准 YOLO (C++ 期望) |
------|----------------------|---------------------|
| 输出数量 | 1 个 (out0) | 3 个 (out0, out1, out2) |
| 输出 shape | [5, 8400] | [64+nc, H_i, W_i] |
| 坐标格式 | 已解码 cx,cy,w,h | 原始 DFL 值 [64] |
| 分类格式 | sigmoid 概率 | logits |
| 锚点 | 已计算（MemoryData） | 需要运行时计算 |
| 后处理 | 已嵌入模型图 | 需要 C++ 实现 |

## 7. C++ 推理代码分析

### 7.1 当前代码的后处理逻辑

```cpp
// yolov11.cpp - generate_proposals()
static void generate_proposals(
    int stride,
    const ncnn::Mat& feat_blob,  // 期望: [64+nc, H, W]
    const float prob_threshold,
    std::vector<Object>& objects
) {
    const int reg_max = 16;
    float dst[16];

    // 1. 遍历所有 anchor
    for (int i = 0; i < feat_blob.h; i++) {
        // 2. 对每个 anchor 的 64 个 DFL 值做 softmax
        //    期望 feat_blob 的 channel 维度 >= 64+nc

        // 3. 从 64 个 softmax 结果中加权求和得到距离值
        //    dist[0] = Σ(j * softmax_j)  // left 距离
        //    dist[1] = Σ(j * softmax_j)  // top 距离
        //    dist[2] = Σ(j * softmax_j)  // right 距离
        //    dist[3] = Σ(j * softmax_j)  // bottom 距离

        // 4. 从距离值计算 cx, cy, w, h
        //    cx = (anchor_x - left + anchor_x + right) / 2
        //    cy = (anchor_y - top + anchor_y + bottom) / 2
        //    w = left + right
        //    h = top + bottom

        // 5. 对分类 logits 做 sigmoid
        //    confidence = sigmoid(cls_logits[class_id])

        // 6. 过滤低置信度检测
    }
}
```

### 7.2 不兼容点分析

| C++ 代码期望 | 实际模型输出 | 后果 |
-------------|------------|------|
 3 个输出 (stride 8/16/32) | 1 个输出 (out0) | 代码读不到 out1/out2 |
 [64+nc, H, W] 每个输出 | [5, 8400] | 维度不匹配，读取越界 |
 64 个 DFL 值做 softmax | 4 个已解码坐标 | softmax 作用在坐标值上产生垃圾 |
 sigmoid(cls_logits) | 已经 sigmoid 的概率 | 双重 sigmoid 压缩概率到极值 |
 需要 grid 解码坐标 | 已解码的 cx,cy,w,h | 双重解码产生垃圾坐标 |

### 7.3 当前代码的输入预处理

```cpp
// 输入预处理（yolov11ncnn.cpp 中）
// 1. resize 到 640×640
// 2. BGR → RGB 转换  ← 实际模型期望 RGB，但此转换可能未执行或错误
// 3. 归一化 /255.0
```

**问题**: 如果 C++ 端没有正确执行 BGR→RGB 转换，会导致红蓝通道互换，影响检测精度。

## 10. 修复建议与优先级

### 10.1 方案 A：修改 C++ 代码适配 ultralytics 标准 NCNN 导出（推荐）

**优势**：C++ 代码改动最小，直接适配 ultralytics 官方导出格式
**劣势**：需要理解 ultralytics NCNN 导出的输出格式

#### 需要修改的内容

1. **移除 generate_proposals() 中的 DFL 解码逻辑**

```cpp
// 旧代码（错误）
static void generate_proposals(int stride, const ncnn::Mat& feat_blob, ...) {
    const int reg_max = 16;
    float dst[16];
    // ... DFL softmax + grid 解码
}

// 新代码（正确）
static void generate_proposals_new(const ncnn::Mat& out0, int nc, ...) {
    // out0 shape: [4+nc, 8400]
    // [0]: cx, [1]: cy, [2]: w, [3]: h (已解码，像素值)
    // [4..4+nc-1]: sigmoid 概率

    for (int i = 0; i < 8400; i++) {
        float cx = out0[0 * 8400 + i];
        float cy = out0[1 * 8400 + i];
        float w  = out0[2 * 8400 + i];
        float h  = out0[3 * 8400 + i];

        // 找最大类别（已经是 sigmoid 概率，不需要再 sigmoid）
        float max_prob = 0;
        int class_id = 0;
        for (int c = 0; c < nc; c++) {
            float prob = out0[(4 + c) * 8400 + i];
            if (prob > max_prob) {
                max_prob = prob;
                class_id = c;
            }
        }

        if (max_prob > prob_threshold) {
            Object obj;
            obj.label = class_id;
            obj.prob = max_prob;
            // 像素坐标 → 归一化坐标（需要知道输入尺寸）
            obj.rect = cv::Rect(
                (cx - w/2) / 640.0f,  // x1 归一化
                (cy - h/2) / 640.0f,  // y1 归一化
                w / 640.0f,           // width 归一化
                h / 640.0f            // height 归一化
            );
            objects.push_back(obj);
        }
    }
}
```

## 11. 关键结论

### 11.1 根因总结

**ultralytics 的 NCNN 导出会自动将完整的后处理流程（DFL 解码 + 锚点计算 + sigmoid）嵌入到模型图中**，导致：
- 输出从 3 个头变为 1 个头
- 输出从原始 DFL 值变为已解码坐标
- 输出从 logits 变为 sigmoid 概率

C++ 推理代码期望的是**原始 YOLO 输出格式**，因此对已处理的数据再次执行相同处理，产生完全错误的结果。

### 11.2 修复优先级

1. **最高优先级**：修改 C++ 推理代码适配 ultralytics 标准 NCNN 导出格式
2. **高优先级**：更新文档和元数据记录
3. **中优先级**：添加格式自动检测和兼容性
4. **低优先级**：代码质量改进和模板修正

### 11.3 长期建议

1. **锁定 ultralytics 版本**：在 requirements.txt 中设置版本上限，避免导出行为变化
2. **添加导出验证**：导出后自动用测试图片验证推理结果
3. **维护格式文档**：明确记录模型的输入输出格式要求
4. **考虑使用 ONNX Runtime**：如果性能要求不高，可以考虑在 Android 上使用 ONNX Runtime 而非 NCNN，ONNX 格式更容易控制后处理
